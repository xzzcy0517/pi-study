# 02 · 执行 `./pi-test.sh` 之后，发生了什么（先看大概）

> **本篇定位**：`pi-test.sh` 这个脚本你已经啃完了（见支线「pi-test.sh 陪读教程」）。按下回车之后，到屏幕上出现交互界面，**中间这一段路**发生了什么？
>
> **只梳理大概**——每一站只讲「是什么、为什么」，不讲实现细节。看懂了轮廓，将来想深挖哪一站，我们再开对应的支线慢慢抠。

---

## 1. 你的直观体验

在终端敲下 `./pi-test.sh`、按下回车后，你会经历：

1. 终端**安静一两秒**（好像什么都没发生——其实后台在忙）；
2. 屏幕**一闪**，顶部出现 Pi 的标志和几行快捷键提示；
3. 中间是空的**对话区**，下方一个**输入框**（光标在闪），最底部一条**状态栏**（显示当前目录、模型等信息）。

从回车到界面出现，通常几秒钟。这段「安静的时间」里，Pi 一口气坐完了**六站地铁**。

---

## 2. 六站地铁（全程大概）

```text
你按回车：./pi-test.sh（bash 脚本，已完成它的使命：点火）
  │
  ├─ 第 1 站：node 启动 Pi 主程序            「点火」
  ├─ 第 2 站：读参数，决定这次要干什么        「听懂你的话」
  ├─ 第 3 站：准备运行环境                    「备料」
  ├─ 第 4 站：组装界面的各个零件              「搭舞台」
  ├─ 第 5 站：画出第一帧画面                  「开幕」
  └─ 第 6 站：进入循环：等你打字              「开演」
```

## 3. 每站用人话说

**第 1 站 · 点火**
bash 脚本把「翻译官」（source-resolver）和你传的参数交给 node，node 开始读 Pi 的入口文件。从此主角换成 node 里的 Pi，bash 脚本退休。

**第 2 站 · 听懂你的话**
Pi 先看你这次想干嘛：带了 `--help`？打印帮助就结束。带了 `--model`？记住这个模型。**什么都没带、且终端是正常交互状态**？——那就是要进交互界面，继续往下走。（如果你把 pi 接到别的程序后面用，它会走另一种「一次性输出」模式，不开界面。）

**第 3 站 · 备料（最安静的一站）**
屏幕没动静的一两秒主要耗在这里。Pi 在后台做准备：读你的配置（`~/.pi/agent/` 里的设置文件）、确定用哪个模型、检查登录状态、把工具箱摆好（读文件、执行命令等工具）、看看有没有要恢复的历史会话。全部在内存里静默完成，**还没往屏幕上画任何东西**。

**第 4 站 · 搭舞台**
Pi 把界面拆成几个「零件」：顶部标志和快捷键提示、中间对话区、输入框、底部状态栏。零件先造出来，还没通电点亮。

**第 5 站 · 开幕**
零件装好后画**第一帧**：终端切成「raw 模式」（键盘从此直接交给 Pi 处理，你打的每个键 Pi 立刻知道），然后一口气把第一屏画出来——你看到的标志、快捷键、输入框、状态栏，全是这一帧的内容。

**第 6 站 · 开演（此后一直循环）**
界面停在这里等你：光标在输入框闪烁，你打字、回车 → Pi 把话转给模型 → 回复一条一条出现在对话区、状态栏实时变化 → 然后继续等你。直到你按 `Ctrl+D`（或连按两次 `Ctrl+C`）退出。

---

## 4. 自己动手观察这几站

| 命令 | 你会看到 | 说明 |
|---|---|---|
| `./pi-test.sh --version` | 打印 `1.1.0` 就结束 | 第 2 站就下车了（不用开界面） |
| `./pi-test.sh --help` | 打印帮助就结束 | 同样第 2 站下车 |
| `./pi-test.sh` | 走完六站，停在等你打字 | 完整旅程 |

想感受第 3 站的「安静」：启动时留意屏幕——标志出现之前那一两秒，就是备料时间。
