## 一句话答案

**`pi-test.sh` 是 Pi 的启动器**：它不实现 Pi 的任何功能，只负责「用正确的方式把 Pi 从源码启动起来」，启动完成就退到一边。

打个比方：Pi 是一台机器，`pi-test.sh` 是**开机按钮**。你按一下，它做三件小事，屏幕上出现的是机器本身（Pi 的交互界面），不是按钮。

---

## 输入是什么？

| 输入 | 内容 | 谁在用 |
|---|---|---|
| **命令行参数** | 你敲在后面的东西，如 `--help`、`--model xxx` | 脚本只留 `--no-env`，其余全部转交 Pi |
| **环境变量** | 终端里的各种密钥（如 `DEEPSEEK_API_KEY`） | Pi 启动时读取；带 `--no-env` 时脚本先清掉 35 个密钥变量 |
| **当前目录** | 你在哪个文件夹运行它 | 脚本原样保留——Pi 会把这里当成「工作目录」，分析你当前的项目 |

## 做了哪几件事？

```text
./pi-test.sh 你传的参数……
  │
  ├─ 第 1–2 行    声明用 bash 运行 + 立纪律（出错就停）          [第 1 讲]
  ├─ 第 4 行      算出自己的绝对住址，记在 SCRIPT_DIR           [第 2 讲]
  ├─ 第 7–15 行   分拣参数：--no-env 留下，其余装进 ARGS 筐     [第 3 讲]
  ├─ 第 17–55 行  （仅 --no-env）清空 35 个密钥变量            [第 4 讲]
  ├─ 第 57–58 行  把「翻译官文件」的地址转成网址               [第 5 讲]
  └─ 第 59 行     点火：node 先装翻译官、再启动 Pi、递上参数    [第 6 讲]
       │
       ▼
   脚本下班，Pi 接手：解析参数 → 组装运行时 → 弹出交互界面
```

三件大事串起来就是：**做准备 → 整理输入 → 点火**。就这么简单。

## 作者为什么需要它？（三个设计意图）

这些都能在仓库的 README 里找到原话（不是推测）：

1. **免构建跑源码**——`./pi-test.sh # Run pi from sources`：改了源码立刻生效，不用等编译；
2. **从任意目录都能跑**——脚本第一步就是「算出自己的住址」，所以你在哪调用它都行；
3. **不抢你的工作目录**——Pi 是编程助手，它分析的是「你当前所在的项目」，所以脚本全程不搬家。

## 常见问题

**Q：脚本能用在别的项目上吗？**
不能。它是 Pi 这个仓库专属的启动器（住址里写死了要找 `packages/coding-agent/src/cli.ts`）。

**Q：`--no-env` 会把我终端里设置的密钥删掉吗？**
不会。它只删「这次启动的行李」，你自己的终端纹丝不动（第 4 讲的实验已经验证）。

**Q：我可以改这个脚本吗？**
学习实验请改 `c-pi/labs/` 里你自己复制的脚本练手，别动 `pi/` 里的原文件。
